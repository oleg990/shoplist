# Push-уведомления

Когда приложение закрыто, остальные участники списка узнают об изменениях через push. Отправка идёт через [Expo Push API](https://docs.expo.dev/push-notifications/sending-notifications/): серверу не нужны отдельные интеграции с FCM и APNs, достаточно токена устройства от Expo.

## Что приходит

| Событие | Заголовок | Текст |
|---|---|---|
| Добавлена позиция | название списка | `Добавлено: Молоко (Оля)` |
| Добавлено несколько позиций подряд | название списка | `Добавлено 5: Хлеб, Молоко, Яйца и ещё 2 (Оля)` |
| Отмечена последняя неотмеченная позиция | `Всё куплено` | `В списке «Продукты» отмечены все позиции (Оля)` |

Уведомление получают все устройства остальных участников списка, но не автор изменения. Позиции, добавленные одним человеком в течение 20 секунд, объединяются в одно уведомление. Если у человека не задано имя, в тексте будет «Кто-то». Правка уже существующей позиции и повторная отметка «куплено» уведомлений не создают. В данных уведомления есть `list_id` и `kind` (`items` или `completed`), по ним приложение открывает нужный список.

## Как приложение подключает устройство

1. Получить push-токен через `expo-notifications` (`ExponentPushToken[...]`), запросив у пользователя разрешение.
2. Отправить его на сервер после входа и при каждом запуске (токен может смениться): `PUT /api/v1/devices` с телом `{"expo_push_token": "...", "platform": "android" | "ios"}`. Повтор безопасен. Если телефон перешёл другому человеку, токен переписывается на того, кто вошёл последним.
3. Перед выходом из аккаунта вызвать `DELETE /api/v1/devices` с тем же токеном.

У пользователя хранится не больше 20 устройств (старые удаляются). Если Expo сообщает, что токен больше не действует (`DeviceNotRegistered`), сервер удаляет его сам.

## Настройки сервера

По умолчанию ничего настраивать не нужно. `EXPO_ACCESS_TOKEN` требуется, только если в проекте Expo включена защита push-токенов (Access token в настройках проекта на expo.dev). `EXPO_PUSH_URL` нужен только для тестов.

## Ограничения

- Уведомления второстепенны: при сбое Expo сервер ничего не повторяет, приложение всё равно догонит данные при открытии (`?since=N`).
- Объединение уведомлений хранится в памяти одного процесса. При нескольких копиях сервера или перезапуске в момент окна возможны лишние или объединённые иначе уведомления. При остановке сервера отложенные уведомления отправляются.
- На iOS push работает только в собранном приложении с аккаунтом Apple Developer, в Expo Go на iPhone (SDK 53+) удалённые уведомления недоступны. Это проверяется на этапе мобильного приложения.
