# Архитектура

Кратко; полное обоснование в [plan.md](plan.md).

- **Сервер** (`server/`): HTTP API на chi. Слои: `httpapi` (обработчики) → `store` (код, сгенерированный sqlc) → Postgres. Настройки только из переменных окружения (`internal/config`).
- **Миграции**: goose, встроены в бинарник (`server/migrations`), применяются при старте.
- **Справочник**: общий для всех, поиск с опечатками через `pg_trgm` (`word_similarity`).
- **Позиции списка**: `id` создаёт клиент (чтобы работать офлайн), `version` растёт при каждом изменении (`item_version_seq`), удаление мягкое. На этом строится синхронизация (раздел 2 плана).
- **Вход**: email + одноразовый код, только собственные аккаунты. Таблица `auth_identities` допускает добавление Google/Apple позже.

Что ещё не сделано: авторизация, списки и участники, `/sync`, WebSocket, push, мобильное приложение.
