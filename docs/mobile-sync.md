# Офлайн-режим и синхронизация в приложении

Код: `mobile/src/sync/`, хук `mobile/src/items/useListItems.ts`.

## Идея

Экран никогда не ждёт сеть. Он читает локальное состояние и пишет в него; движок `SyncEngine` отправляет правки
на сервер и забирает чужие, когда есть связь.

- **base** — то, что подтвердил сервер (позиции по спискам и курсор `since` каждого списка).
- **ops** — очередь неотправленных правок позиций: `put`, `patch`, `delete`, `clear`.
- **Что видит пользователь** = base + очередь, наложенная сверху. Если сервер отверг правку, она просто выпадает из очереди,
  и на экране снова состояние сервера. Поэтому отдельно «откатывать» ничего не нужно.

Всё сохраняется в SQLite (таблица `kv`: ключ → JSON; списки, позиции по спискам, очередь). Для списков покупок объёмы
небольшие, поэтому целиком грузим в память при старте. Если когда-нибудь понадобятся запросы по полям, схему можно
заменить, не трогая экраны: они видят только интерфейс движка.

## Отправка

Правки идут по порядку. Сервер принимает их идемпотентно (PUT с id от клиента, PATCH, DELETE), поэтому после обрыва
связи повтор безопасен.

- Сеть пропала, 5xx, 429 или 401 (не удалось обновить токен) → правка остаётся в очереди, повтор позже, статус «нет связи».
- Сервер ответил 4xx (список удалён, позиции нет, неверные данные) → правка снимается, показывается сообщение, дальше pull возвращает правду. Удаление уже удалённой позиции ошибкой не считается.
- Правка ещё не отправленной позиции сливается с её `put`/`patch`. Правка той, что отправляется прямо сейчас, ставится отдельным патчем, иначе её можно потерять.

## Получение

После отправки движок запрашивает список списков и `GET /lists/{id}/items?since=<курсор>` по каждому из них.
Версии растут per-list под блокировкой на сервере, поэтому курсор не пропускает поздние коммиты (см. `architecture.md`).
Список, которого больше нет на сервере, стирается вместе со своими правками.

## Когда синхронизируемся

- при старте и входе;
- через 300 мс после локальной правки (несколько быстрых правок уходят вместе);
- по WebSocket: `list_changed` для позиций → pull одного списка, остальное и `ready`/`resync` → полная синхронизация;
- когда приложение возвращается на передний план;
- раз в 30 секунд, если нет связи или есть неотправленное.

WebSocket (`realtime.ts`) переподключается с паузой 1→30 с; на код 4401 обновляет токен и подключается сразу.

## Что пока работает только онлайн

Вход по коду приглашения, удаление списка, участники и приглашения требуют интернета.
Полностью офлайн работают позиции (добавление, отметки, правка, удаление, «очистить купленное»), а также создание и переименование списков.

Новый список получает id на устройстве и уходит на сервер операцией `listCreate` (`PUT /lists/{id}`, идемпотентный: повтор владельца возвращает 200, чужой или удалённый id даёт 409). Очередь отправляется по порядку, поэтому позиции нового списка уходят после его создания. Пока список не отправлен, экран участников и приглашения недоступны (сервер его ещё не знает).

## Данные на устройстве

Локальная база принадлежит одному пользователю: при выходе она стирается, а при входе другого пользователя
чужие данные удаляются.
